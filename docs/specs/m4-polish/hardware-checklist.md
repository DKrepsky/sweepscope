# M4 hardware checklist (run by the human on the Hantek 6254BC)

Closes what the simulator cannot prove: the shorted-input rules, the offset assumptions and the CLI on a real device. Spec: [implementation-spec.md](implementation-spec.md) section 7. Agents never touch the scope. About 50 minutes. Critical path only.

Setup unless stated: your real desktop session, installed or built app (`npm run dev`), `RUST_LOG=info`, probes disconnected from every circuit, 1x probes, DC. "Short" means probe tip to its own ground clip, or BNC centre to shell. **Never short a live circuit.** Keep measured figures in your own notes (ADR 0008); the QA report carries outcomes. Back up `~/.config/io.github.dkrepsky.sweepscope/zero-offsets.json` first if you want to keep an earlier calibration.

| ID | Do | Expect |
|---|---|---|
| H-M4-1 | Start with no offsets file. Click `NO CALIBRATION`, Start, short CH1, Calibrate; repeat for CH2 to CH4. Time each channel. Finish with Done. | Each channel takes under 40 s (simulator: about 5 s). Progress rises step by step. Done table shows 12 ranges by 4 channels; 2, 5, 10, 20 mV/div values near +0.7 to +1 mV and 50 mV/div and above within about 100 uV (one unit measured, yours may differ: record the table). Tag turns `CALIBRATED`; hovering shows date and offsets. |
| H-M4-2 | Open input, no probe, CAL probe on CH2 only. Calibrate CH1. Then CH1 with the probe lying open on the bench (quiet open input), then touching the probe tip with a finger. | Channel next to the calibrator: not-shorted note with the measured numbers (peak to peak or level), nothing stored, `Try again` works after shorting. Quiet open input and finger: record whether each is accepted or rejected and the numbers shown (PRD 5.2: a quiet open input may pass; this is a threshold datum, not a pass or fail). |
| H-M4-3 | After H-M4-1, short each input in turn and read the CH value in the measurement panel (Mean) at 2, 5 and 10 mV/div; then CAL on CH1 at 1 V/div. | Shorted mean within one count (1/24 division) of 0 V at 2, 5, 10 mV/div for every channel (uncalibrated: about 8, 5, 2 counts off). CAL still reads about 1.9 V peak to peak at 1 V/div (offset at 1 V/div is about zero). |
| H-M4-4 | Offset independence. With the calibration from H-M4-1 and a shorted CH1: read Mean at 2 mV/div with (a) CH1 only at 2 us/div, (b) four channels at 200 us/div, (c) AC coupling, (d) bandwidth limit on, (e) position -3 div and +3 div. | Within one count of 0 V in (a) to (d). In (e) up to 2 to 3 counts is the stated limit; record the counts. If (a) differs from (b) by more than one count, the single-channel mode (k = 1) assumption fails: report it. |
| H-M4-5 | Calibrate, close the app, unplug and replug the scope, restart the app. Then calibrate with the scope on another USB port. | Tag is `CALIBRATED` after replug and restart (same unit identity; the log shows one unit id). Another port keeps the same state. Note the unit id format in the log if it is shown, and whether the scope reports a serial-like value at all (if it does not, the tag is disabled with a reason). |
| H-M4-6 | CLI on the real scope (close the app first). Save a setup file from the app. Run `sweepscope capture --setup s.json --count 3 --out /tmp/cap` (the installed `.deb` command, see [install.md](../../install.md); a source build is `target/release/sweepscope`). Then: scope unplugged with `--device-wait 3`; a Normal sweep with the trigger level above the signal and `--timeout 2`; an output folder that is read only; a bad option. Check `echo $?` each time. Then run the AppImage from another working directory, the one holding `s.json`, with relative paths: `/path/to/SweepScope_<version>_amd64.AppImage capture --setup s.json --count 3 --out cap`. | 0 with three files; 10 within about 3 s; 11 after about 2 s; 12 for the read-only folder (and, without the udev rule or as another user, for USB permission); 2 for the bad option. Files of the first run open (CSV, or raw with `capture.format.txt`) and `ch1_zero_offset_applied: true` after H-M4-1. The config folder is unchanged (compare checksums before and after). AppImage run: 0 and three files in `cap` under the directory you ran it from. |
| H-M4-7 | Shorted-input rules and Continue. (a) Short CH1, CH2, CH3, CH4 properly one by one at the default setup and calibrate: all four must be accepted with no `Continue` offered (a real short read 1.45 mV at 2 mV/div before the limit became 2.5 mV). (b) Make one input deliberately noisy or biased (wiggle the clip, a long unshielded lead near mains, a 3 mV source) and calibrate that channel. (c) At the rejection press `Try again` once, then `Continue`. (d) Finish the other channels, `Done`. | (a) Four channels, no not-shorted note, Done lists no accepted line. (b) The not-shorted note with numbers in volts and the limit, buttons `Cancel`, `Continue`, `Try again`, warning line under the steps. A clipped reading at the 100 mV/div gate offers no `Continue`. (c) `Try again` measures again; `Continue` moves on at once and no check runs on the later ranges. (d) Done table and one quiet line `CHn accepted although the input did not look shorted`; tag `CALIBRATED`; Mean of that shorted input at 2 mV/div is near 0 V only if it really was a short (record it). Record the peak to peak, level and noise at the gate for a good short (constants: 6 codes, 8 codes, 1.5 codes) and the level at 2 mV/div for all four channels. |
| H-M4-8 | Cancel safety. Start a calibration, measure CH1 and CH2, press Esc during CH3 measuring, then press Cancel at the channel 4 step. Look at `zero-offsets.json` and the tag each time. Unplug the scope while a channel is measuring. | Nothing is stored (file and tag unchanged). Unplug shows the device-lost note with one `Close`. After replug the previous setup (channels, ranges, time base, run state) is back as before the dialog. |
| H-M4-9 | `.deb` on a clean machine or VM (Ubuntu 24.04) without WebKitGTK: `sudo apt install ./SweepScope_*.deb`, plug the scope, start the app from the menu. Also run the AppImage on a second machine. | WebKitGTK and GTK come in as dependencies; `/lib/udev/rules.d/99-hantek6xx4.rules` exists and the scope opens without sudo (after replug); the window title, task switcher and launcher show the SweepScope icon; `~/.config/io.github.dkrepsky.sweepscope` is created. The AppImage runs but has no udev rule (install guide covers it). Package name is `sweep-scope`; note whether that is acceptable. |
| H-M4-10 | Visual pass on the real display at 1440 x 900 and at 150 % text scale: tag, tooltip, each dialog step, the Done table, the connection item with the real scope (`Ready Hantek 6254BC`, firmware, FPGA). Open the dialog from the tag with the mouse and with Enter, and step through every step with the keyboard. | No focus ring on the step heading (`Why calibrate`, `Channel n: short the input`, the Done note) at any step; rings remain on buttons and the tag when Tab reaches them. Nothing clipped or overlapping; the status bar shows the tag at the right end; the tooltip is readable and not cut off at the window edge; the connection item has no `Simulator` word; no UNVERIFIED or `?` anywhere, including the time base and range menus when stepping through every range and time base. |
| H-M4-11 | Tooltip rows on the real scope. With and without calibration hover the tag. Set CH1 to 2 mV/div, CH2 to 20 mV/div, CH3 to 1 V/div, CH4 off; then CH1 to a 10x probe (also set the probe on the scope menu of the app); turn a range knob while the tooltip is open. | One row per enabled channel in channel colour, at that channel's range, offset probe scaled (10x: `+6.6 mV at 20 mV/div` style); CH4 has no row; zero shows `0 V`; one number form with and without calibration (known open item BUG-32: `up to ... mV` rows on ranges from 50 mV/div up when not calibrated); rows follow the knob; no Gain, extreme position or Resolution lines. Compare the CH1 to CH4 values with the Done table. |
