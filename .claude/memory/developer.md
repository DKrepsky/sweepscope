## Verified tooling facts
- Cargo workspace glob member with zero matches (missing or empty dir) is a hard error; one file inside (`backend/libs/.gitkeep`) makes it valid. Members that do not exist yet (kernel, src-tauri) also break every cargo command until created.
- `node --test tools` fails on Node 24 (directory is run as a module); use `node --test "tools/*.test.mjs"`.
- `cargo metadata --no-deps` works offline and lists direct deps (name, rename, path) of members: enough for layering rules.
- Cargo `[workspace.lints]` cannot be combined with extra per-crate lints, so `forbid(unsafe_code)` is a `#![forbid(unsafe_code)]` attribute per crate.
- ts-rs latest is 12.x (13 does not exist); tauri crate 2.12.x, `@tauri-apps/cli` 2.12.6; `deny.toml` verified against that tree with cargo-deny 0.22.
- Scratch binaries (actionlint, cargo-deny) can be downloaded from GitHub releases with `gh release download` into the scratchpad; not installed system-wide.

## Lessons
- `git add` with one non-existent path aborts the whole add; check `git show --stat` after committing.
- Verify crates before `src-tauri` exists: scratch workspace in the scratchpad with a symlink to the repo's `backend/`, a Cargo.toml copy without `src-tauri`, and copies of rust-toolchain/rustfmt/clippy toml; run cargo there (generated ts files still land in the repo via the symlink).
- ts-rs 12: `export_to` is relative to `TS_RS_EXPORT_DIR` (default `<crate>/bindings`), so the up-count depends on crate depth (kernel 3, features/* 4). `export_all` takes `&Config` (`Config::from_env()`); `#[ts(export)]` already generates a test that writes the file. `ts-rs` pulls `thiserror`.
- Kernel API facts: `Bus::handle` returns `Result<(), KernelError>` (duplicate refused); `SettingsModule::new` returns `Result`; `CommandDescriptor` lives in kernel, `settings::COMMANDS` is the manifest.

## WP7 lessons (ui containers and feedback)
- `render(Component, { props })` is required when a prop is named `anchor` (Svelte option clash); wrap all props under `props`.
- jsdom lacks `HTMLDialogElement.showModal/show/close` effects: stub them in the test; Escape is simulated by dispatching a cancelable `cancel` event.
- Stylelint rejects `font: inherit`; use `font-family: var(--ss-font-ui)` + size token. ESLint rejects `cond ? a() : b()` statements.
- `<!-- svelte-ignore code: reason -->` makes the reason parse as codes (no-unused-svelte-ignore errors): put the reason in a separate comment.
- Inline children render with whitespace between them: assert text with spaces (`'1.20 ? V'`).
- Tooltip (WP6) wraps in an inline-flex span, shows on focusin: make the child focusable (tabindex 0 or a button).

## UI component facts (WP6)
- Svelte component pattern: `<script module lang="ts">` exports the props interface, `index.ts` re-exports component and type; conditional tooltip wrap via a local `{#snippet control()}` rendered inside or outside `<Tooltip>`.
- Stylelint bans `px`, `font: inherit` and `font-family: inherit` in ui (use `var(--ss-border-width)` for 1px offsets, `var(--ss-font-mono)`); tsconfig has noUncheckedIndexedAccess (use `?.` on array reads).
- Tests: fake timers need `userEvent.setup({ advanceTimers: vi.advanceTimersByTime })`; jsdom does not parse `ch` units in `toHaveStyle` (assert the style attribute); `$props.id()` gives unique ids for aria-describedby.
- Segmented: arrows skip disabled options, but all options are Tab stops so a disabled option's reason is reachable (AC-I13).

## Graph and Marker facts (WP8)

## Device module facts (M1 WP3)
- `device/src/module/`: `manager.rs` (state machine thread, one inbox `Msg`), `worker.rs` + `control.rs` (per-session thread, intent in `WorkerControl` with a Condvar, latest setup wins), `connection.rs` (`ConnectionStore` owns revision and publishes only on change), `session.rs` (`end()` joins within 250 ms via a done channel), `issue.rs` (error to banner).
- Catalog events are forwarded by one thread per catalog that polls a stop flag every 20 ms (catalog `Receiver` cannot be woken); `DeviceModule::drop` joins them.
- `SimulatorControl::new()` starts plugged; the shell must `unplug()` it before building the module unless `SWEEPSCOPE_SIMULATOR=1`. A simulator `Attached` publishes `simulator_active` together with the following state (`defer_simulator_active` + `flush`) to avoid an extra event.
- Tests: `tests/module_support/mod.rs` (`Source` with `Hooks`: open/capture error injection, a capture gate, live-device and configure counters). Subscribe a recorder before `DeviceModule::new` to see the first `Disconnected`. The thread-count test lives alone in its file because it counts process threads.
- `cargo fmt --all` before clippy; clippy `too_many_lines` limit is 40 per function.

## WP10 lessons (live model, waveform)
- `src/**` lint bans `node:` imports, and vite `fs.allow` blocks files outside `frontend/` (`?inline` of `backend/...` fails): cross-repo fixture tests live in `frontend/tools/*.test.ts` (vitest includes `tools/**`), with `// @vitest-environment node` and `/// <reference types="node" />`.
- ESLint `max-lines-per-function` is 40: split action maps into group builders. Prettier reformats long one-liners, run it before lint.
- A default parameter value applies when `undefined` is passed: use an option flag to model "no instrument" in test setups.
- `api/index.ts` exports few generated types; derive them (`InstrumentState['controls']['run']`) instead of editing WP9 files.
- Model sources: `LiveMainWindow` = `Readable<MainWindowModel> & MainWindowActions` (same shape as the mock); selectors are pure `select-*.ts`; test the model through writable fake stores.
## Acquisition module facts (M1 WP6)
- `acquisition/src/module/`: `core.rs` (all state and rules, returns `Effects` of outputs and device calls, never touches the bus), `shared.rs` (`turn` lock orders whole steps so the device sees setups in revision order; `core` lock never held across a bus call), `handlers.rs` (weak refs to `Shared`: bus handlers live forever, a strong ref would be a cycle), consumer thread in `mod.rs` (drains `ConnectionChanged` first, then `recv_timeout(20 ms)` on `CaptureCompleted`, tick refreshes facts).
- The architecture check counts dev-dependencies, so a feature crate cannot dev-depend on `device`: module tests use a `FakeDevice` on the bus (`tests/module_support`); the real `DeviceModule` plus `AcquisitionModule` integration test belongs in `src-tauri` (WP8). The shell must create `AcquisitionModule` before `DeviceModule` (no way to ask for the current connection).
- Test sync: events are handled FIFO, so a sentinel frame published after the event under test proves it was handled; advance `FakeClock` only after the consumer processed the previous frame, or all frames get the same instant.
- Clippy `large_enum_variant` hits `Output` enums holding slices: box the big variants.

## M2 WP1 lessons (contracts)
- ts-rs `export_to` is relative to the source file's directory depth: kernel `src/*.rs` uses 3 `../`, `src/contracts/*.rs` and `features/*/src/*.rs` use 4. A wrong count writes `backend/frontend/...` and bad import paths in other generated files.
- Library crates are named without prefix (`interpolation`, `measurements`, `engineering-format`); features `sweepscope-<name>`. Rust 1.100 warns on unused dependencies: add a dependency only when code uses it.
- Compound shell commands (heredoc plus python plus cat) get refused in worktrees; use Write/Edit tools and one simple command per call.
- Root can bypass read-only folder permissions: tests of `PermissionDenied` probe writability first.

## WP7 export (developer-5)

## M2 WP5 display (developer-1)
- Integer rule: factor = clamp(ceil(2500 / (len - 1)), 1, 512); automatic Sinc iff 1 <= len-1 < 2500. `encode_in_mode` is the mode-aware encoder, `encode` stays the Linear one. Module state (mode, last frame, sequence) sits behind one Mutex shared by the worker and the request handlers; handlers publish events synchronously, so tests need no sleeps.
- A 200 ns window (20 ns/div) cannot hold a 250 ns edge: the rise-time test measures 20-80 % and scales by 0.8/0.6.
- clippy `too_many_lines` limit is 40 per function.
